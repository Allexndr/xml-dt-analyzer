1. **Примеры деклараций.** 10–20 реальных XML-файлов, по возможности разных: с маркировкой и без неё, разные процедуры, крупные файлы. Персональные данные можно обезличить. Для каждого файла укажите ожидаемые значения: количество товаров, количество кодов маркировки по товарам, документы в графе 44. Эти значения станут эталоном приёмки.
2. **Формат файлов.** В каком формате пользователи получают XML: структура ЕЭК R.055, формат ИС «Астана-1», формат ФТС России или формат программы-декларанта? Если файлы не в R.055, пришлите, пожалуйста, их схемы или укажите, где их взять.
3. **Локальный ИИ.** Что имеется в виду:
   (а) сайт работает в облаке, а ИИ-модель запущена на компьютере пользователя;
   (б) весь сервис устанавливается у вас или у клиента и не передаёт данные наружу?
4. **Нормативные тексты.** Портал adilet.zan.kz выдаёт тексты только через API с ключом доступа. Можете ли вы получить такой ключ? Если нет, согласны ли вы на консолидированные тексты из коммерческих справочных систем (Альта-Софт, КонсультантПлюс) с указанием источника?
5. **Юрисдикция.** Проверять правила только Республики Казахстан или всех государств ЕАЭС? Структура R.055 содержит 73 реквизита, порядок заполнения которых зависит от страны.
6. **Эксперт.** Нам нужен специалист по таможенному декларированию примерно на 2 дня в неделю. Он подтвердит соответствие граф ДТ элементам XML и выберет первые 15–30 проверок для первой версии.
